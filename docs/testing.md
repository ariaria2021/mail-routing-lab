# テストガイド

## 実行方法

Node.js 24を使います。依存関係を入れた後、すべての自動テストと本番ビルドを実行します。

```bash
npm ci
npm test
npm run build
```

`npm test` は Vitest を使い、ブラウザ相当のDOM環境（jsdom）で実行します。GitHub Pagesへの公開ワークフローでも同じテストとビルドを実行します。

## テストの種類

| 対象 | ファイル | 確認すること |
| --- | --- | --- |
| 配送ルール | `src/engine.test.ts` | MX未設定、優先度順の配送、停止時のフェイルオーバー、容量不足時に予備MXへ切り替えないこと、メールアドレスのドメイン抽出、配送ステップ列 |
| ステージ設定 | `src/game.test.ts` | 各ミッションの初期状態と、指定サーバーへ配送した場合だけクリアになること |
| 画面とゲーム進行 | `src/main.test.ts` | 失敗の観察後の段階ヒント、MX修正、予備サーバー起動、容量増加、配送経路の再生、3ステージのゲームクリアまでのUI操作 |

## テスト追加の目安

配送の判定ルールを変える場合は、まず `src/engine.test.ts` に成功・失敗のケースを追加します。新しいステージやクリア条件を作る場合は `src/game.test.ts` に初期状態とクリア条件を追加します。

プレイヤーの操作手順、画面遷移、保存状態に関わる変更は `src/main.test.ts` に追加します。テストでは `mount()` がゲームを初期状態で描画し、`submit()` がフォーム送信を再現します。画面を再描画する操作の後は、対象の要素を改めて `document.querySelector()` で取得してください。

## 公開前の手動確認

自動テストに加え、`npm run dev` で起動して次を確認します。

1. 初期状態から3つのミッションを順にクリアできる。
2. 配送失敗時に、ログと失敗理由が表示される。
3. リロード後もゲームの進行状態が残る。
4. スマホ幅でも入力欄とボタンを操作できる。

実メール、実DNS、外部ネットワークへの送信は行わないため、ローカル環境で安全に実行できます。
