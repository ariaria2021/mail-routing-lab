# Mail Routing Lab 仕様書

## 1. プロダクトの目的

メール配送の基本である「宛先ドメインの MX レコードを DNS で取得し、優先順位に従って SMTP サーバーへ配達を試みる」流れを、短時間で手を動かして理解する教育ゲームです。実在のDNS、SMTP、メールアドレスへは接続しません。

想定する利用者は、Web 開発経験があり、メール配送インフラの入口を視覚的に学びたい人です。

## 2. MVP のルール

プレイヤーは `example.local` の管理者です。宛先は `bob@example.local` とし、DNS Zone にある MX レコードが配送先候補になります。

1. 送信時、宛先アドレスからドメインを取り出す。
2. 対象ドメインの MX レコードを優先度の小さい順に探索する。
3. ホストが存在し、稼働中で、メールボックスに空きがあれば受信する。
4. 条件を満たさない候補はログに理由を残し、次の MX を試す。
5. 成功したメールだけを bob の受信ボックスに追加する。

初期状態では MX が `mail-broken.example.local` を向くため失敗します。`mail.example.local` に修正して成功させることが最初のミッションです。

## 3. データと画面

ゲーム状態は `localStorage` の `mail-routing-lab-state` に JSON で保存します。含むデータは MX レコード、SMTP サーバーの稼働状態・容量・使用数、受信メール、直近の配送ログです。

- **DNS Zone**: 優先度とホスト名を編集する。MVPでは1レコードを編集する。
- **SMTP サーバー**: 起動・停止と容量を表示する。停止と容量切れは配送失敗の原因になる。
- **メール作成**: From / To / 件名 / 本文を入力し、配送エンジンを呼ぶ。
- **配送ログ**: DNS照会、MXごとの接続試行、SMTPの簡略会話、成功または失敗理由を表示する。
- **受信ボックス**: 成功したメールを新しい順に表示する。

## 4. 非目標と安全性

本アプリは実メールサーバーではありません。SMTP プロトコルの待受、DNS ゾーンの公開、ユーザー認証、外部メール配信は実装しません。実配信には TLS、迷惑メール対策、SPF/DKIM/DMARC、逆引きDNSなど追加の運用要件が必要であり、学習ゲームの範囲外です。

## 5. 検証基準

自動テストはメールアドレスのドメイン抽出、MX未設定時の失敗、MX優先度に沿った配送、容量切れの拒否を対象にします。公開前に、初期状態からMXを修正してメールを1通受信できること、リロード後も状態が残ることを手動確認します。

## 6. 次のバージョン

複数MXの追加・削除とフェイルオーバーのチュートリアルを次に導入します。その後、SPF / DKIM / DMARCを段階的な判定カードとして追加し、迷惑メール・障害・コストを含む運営モードへ拡張します。
